# 🛡️ Network Security Basics — Notes

> 📌 **Note:** Network security is the practice of protecting data, devices, and infrastructure **as it moves across or sits on a network** — defending against unauthorized access, misuse, and attacks.

---

## 🎯 The Core Goals — CIA Triad

|Principle|Meaning|
|---|---|
|**Confidentiality**|Only authorized people/systems can access the data|
|**Integrity**|Data can't be altered/tampered with undetected|
|**Availability**|Systems and data stay accessible when needed|

> 💡 **Tip:** Almost every security concept maps back to protecting one (or more) of these three pillars.

---

## 🔑 Core Security Concepts

### Authentication vs Authorization

|Term|Question it answers|Example|
|---|---|---|
|**Authentication**|_"Who are you?"_|Logging in with a password|
|**Authorization**|_"What are you allowed to do?"_|Admin vs. regular user permissions|

> ⚠️ **These are NOT the same thing** — a user can be authenticated (logged in) but not authorized to access a specific resource.

### Encryption

- **At Rest** — data encrypted while **stored** (e.g. encrypted hard drives, databases).
- **In Transit** — data encrypted while **moving** across a network (e.g. HTTPS, TLS).

|Type|How it works|Speed|
|---|---|---|
|**Symmetric**|Same key encrypts & decrypts|Fast|
|**Asymmetric**|Public key encrypts, private key decrypts|Slower, more secure for key exchange|

## 🧱 Common Security Devices & Tools

### Firewall

- Monitors and **filters incoming/outgoing traffic** based on defined security rules.
- Can be **hardware-based** (a dedicated device) or **software-based** (built into an OS).
- Works by allowing/blocking traffic based on **IP address, port, and protocol**.

### VPN (Virtual Private Network)

- Creates an **encrypted tunnel** between a device and a remote network.
- Hides your IP address and encrypts traffic — useful on **public Wi-Fi**.
- Commonly uses **IPSec** or **TLS-based protocols** (like OpenVPN, WireGuard).

### IDS vs IPS

|System|Function|
|---|---|
|**IDS** (Intrusion Detection System)|**Detects** suspicious activity and alerts admins|
|**IPS** (Intrusion Prevention System)|**Detects AND actively blocks** the threat in real time|

### Proxy Server

- Acts as a **middleman** between a client and the internet.
- Can hide client IP addresses, cache content, or filter traffic.

## ⚠️ Common Network Attacks

|Attack|What it does|
|---|---|
|**Phishing**|Tricks users into revealing credentials via fake emails/websites|
|**Man-in-the-Middle (MITM)**|Attacker secretly intercepts communication between two parties|
|**DDoS (Distributed Denial of Service)**|Floods a server with traffic to make it unavailable|
|**Spoofing**|Faking an IP/MAC/email address to impersonate a trusted source|
|**Malware**|Malicious software (viruses, worms, ransomware, trojans, spyware)|
|**SQL Injection**|Injecting malicious SQL code through unvalidated input fields|
|**Packet Sniffing**|Capturing unencrypted data as it travels across a network|
|**Brute Force Attack**|Repeatedly guessing passwords/keys until access is gained|

> ⚠️ **Unencrypted traffic (HTTP, plain FTP, Telnet) is especially vulnerable to packet sniffing and MITM attacks.** Always prefer encrypted alternatives (HTTPS, SFTP, SSH).

---

## 🔐 Key Security Protocols

|Protocol|Purpose|
|---|---|
|**TLS/SSL**|Encrypts data in transit (basis of HTTPS)|
|**IPSec**|Encrypts/authenticates IP packets — core of most VPNs|
|**SSH**|Secure remote access/command execution|
|**WPA2/WPA3**|Wireless network encryption|
|**Kerberos**|Authentication protocol using "tickets" to verify identity|

## 🏰 Network Security Architecture Concepts

### Network Segmentation

- Dividing a network into smaller isolated segments (**subnets/VLANs**) to limit the spread of an attack.
- If one segment is compromised, the rest of the network stays protected.

### DMZ (Demilitarized Zone)

- A buffer subnet placed **between** a trusted internal network and an untrusted external network (like the internet).
- Public-facing servers (web, email) sit here so that even if compromised, the internal network stays isolated.

### Zero Trust Model

> 📌 **Core idea: "Never trust, always verify."**

- No device or user is automatically trusted, **even if inside the network perimeter**.
- Every request is authenticated and authorized, regardless of origin.

### Principle of Least Privilege

- Users and systems should only have the **minimum access necessary** to perform their function — nothing more.

---

## 🧑‍💻 Authentication Best Practices

- **MFA (Multi-Factor Authentication)** — combining 2+ of: _something you know_ (password), _something you have_ (phone/token), _something you are_ (fingerprint).
- **Strong password policies** — length + complexity + no reuse across sites.
- **Least privilege access control** — don't give admin rights unless truly needed.

> 💡 **Tip:** MFA blocks the vast majority of automated account-takeover attempts, even if a password is leaked.

---

## 🧠 Key Takeaways

- Network security exists to protect **Confidentiality, Integrity, and Availability (CIA Triad)**.
- **Authentication ≠ Authorization** — verifying identity is different from granting permissions.
- **Firewalls, VPNs, IDS/IPS** are the core building blocks of a defended network perimeter.
- Always prefer **encrypted protocols** (HTTPS, SSH, SFTP, WPA2/3) over their unencrypted legacy counterparts.
- **Zero Trust + Least Privilege** are the modern default mindset — assume nothing is safe until verified.
- Most attacks (phishing, MITM, DDoS, spoofing) exploit either **human trust** or **unencrypted/unmonitored traffic** — awareness and encryption solve most of the risk.

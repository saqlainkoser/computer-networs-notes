### `ping`, `tracert`, and `ipconfig`

Command-line utilities built into Windows (and their Linux/macOS equivalents) for testing connectivity, tracing network paths, and viewing network configuration.

---

## 1. `ping`

**Purpose:** Tests whether a host (another device, server, or website) is reachable over the network and measures how long round-trip communication takes.

### How it works

`ping` sends **ICMP Echo Request** packets to a target IP address or hostname. If the target is reachable, it replies with **ICMP Echo Reply** packets. The tool reports whether replies were received, the time taken (latency), and how many packets were lost.

### Syntax

```
ping [options] destination
```

### Common Examples

```bash
ping google.com                 # Ping by hostname
ping 8.8.8.8                    # Ping by IP address
ping -t 192.168.1.1             # Continuous ping (Windows) — Ctrl+C to stop
ping -n 10 google.com           # Send 10 requests (Windows)
ping -c 10 google.com           # Send 10 requests (Linux/macOS)
ping -4 example.com             # Force IPv4
ping -6 example.com             # Force IPv6
```

### Sample Output

```
Pinging google.com [142.250.premium.14] with 32 bytes of data:
Reply from 142.250.x.14: bytes=32 time=14ms TTL=117
Reply from 142.250.x.14: bytes=32 time=13ms TTL=117
Reply from 142.250.x.14: bytes=32 time=15ms TTL=117
Reply from 142.250.x.14: bytes=32 time=14ms TTL=117

Ping statistics for 142.250.x.14:
    Packets: Sent = 4, Received = 4, Lost = 0 (0% loss)
Approximate round trip times in milli-seconds:
    Minimum = 13ms, Maximum = 15ms, Average = 14ms
```

### What to Look For

|Result|Meaning|
|---|---|
|Replies received, low time (ms)|Host is reachable, connection is healthy|
|`Request timed out`|No reply — host may be down, blocking ICMP, or unreachable|
|High/inconsistent time values|Network latency or congestion|
|`Destination host unreachable`|No route to the target from your device|
|100% packet loss|Connection failure between source and destination|

### Key Uses

- Confirming a device or website is online
- Testing local network connectivity (e.g., pinging the router/gateway)
- Diagnosing latency and packet loss issues
- Verifying DNS resolution (pinging by hostname resolves the name to an IP)

## 2. `tracert` (Windows) / `traceroute` (Linux/macOS)

**Purpose:** Shows the **path (route)** data takes to reach a destination, listing every intermediate device (router/hop) along the way and the time taken to reach each one.

### How it works

`tracert` sends packets with **incrementally increasing TTL (Time To Live)** values (1, 2, 3…). Each router that forwards the packet decreases the TTL by 1; when TTL hits 0, that router sends back an "expired" message, revealing itself. This repeats hop-by-hop until the destination is reached — effectively mapping the whole route.

### Syntax

```
tracert [options] destination        (Windows)
traceroute [options] destination     (Linux/macOS)
```

### Common Examples

```bash
tracert google.com              # Windows
traceroute google.com           # Linux/macOS
tracert -d google.com           # Don't resolve hostnames (faster, Windows)
tracert -h 15 google.com        # Limit to 15 hops maximum (Windows)
traceroute -m 15 google.com     # Limit to 15 hops (Linux/macOS)
```

### Sample Output

```
Tracing route to google.com [142.250.x.14]
over a maximum of 30 hops:

  1     2 ms     1 ms     1 ms  192.168.1.1
  2    10 ms     9 ms    10 ms  10.10.0.1
  3    15 ms    14 ms    15 ms  isp-gateway.net [203.0.113.1]
  4    22 ms    21 ms    22 ms  core-router.isp.net [198.51.100.5]
  5    14 ms    13 ms    14 ms  142.250.x.14

Trace complete.
```

### What to Look For

|Result|Meaning|
|---|---|
|Steady, low times at each hop|Healthy route|
|Sudden spike in time at one hop|Congestion/slowdown at that specific point|
|`* * *` (asterisks/timeouts)|That hop didn't respond (may still forward traffic — not always a problem)|
|Trace stops before destination|A firewall or routing issue is blocking traffic partway through|

### Key Uses

- Identifying **where** in the network a connection problem is occurring (your network, ISP, or destination)
- Diagnosing slow connections by pinpointing which hop adds delay
- Understanding the physical/logical path traffic takes across the internet

## 3. `ipconfig` (Windows) / `ifconfig` or `ip addr` (Linux/macOS)

**Purpose:** Displays (and can modify) the current TCP/IP network configuration of your own device — IP address, subnet mask, default gateway, DNS servers, etc.

### Syntax

```
ipconfig [options]          (Windows)
ifconfig [options]          (Linux/macOS — legacy)
ip addr show                (Linux — modern)
```

### Common Examples

```bash
ipconfig                    # Basic info: IP, subnet mask, gateway
ipconfig /all               # Full details: MAC address, DNS, DHCP, hostname
ipconfig /release            # Release current DHCP-assigned IP address
ipconfig /renew              # Request a new IP address from DHCP
ipconfig /flushdns           # Clear the local DNS resolver cache
ifconfig                     # Linux/macOS equivalent of basic ipconfig
ip addr show                 # Modern Linux equivalent
```

### Sample Output

```
Ethernet adapter Ethernet:

   Connection-specific DNS Suffix  . :
   IPv4 Address. . . . . . . . . . . : 192.168.1.42
   Subnet Mask . . . . . . . . . . . : 255.255.255.0
   Default Gateway . . . . . . . . . : 192.168.1.1
```

### Key Fields Explained

|Field|Meaning|
|---|---|
|**IPv4 Address**|Your device's address on the local network|
|**Subnet Mask**|Defines the size/boundary of the local network|
|**Default Gateway**|The router your device sends outbound traffic through|
|**DNS Servers**|Servers used to resolve domain names to IP addresses|
|**Physical (MAC) Address**|Hardware address of the network adapter|
|**DHCP Enabled**|Whether the IP was assigned automatically|

### Key Uses

- Finding your device's own IP address and network settings
- Diagnosing IP conflicts or misconfiguration
- Renewing/releasing a DHCP lease when a connection misbehaves
- Flushing DNS cache to fix stale/incorrect domain lookups
- A first step in almost any network troubleshooting session

## Quick Comparison

|Tool|Checks|Answers the question|
|---|---|---|
|`ping`|Reachability & latency to a target|"Is it up, and how fast?"|
|`tracert` / `traceroute`|The path/route to a target|"Where exactly is the problem?"|
|`ipconfig` / `ifconfig`|Your own device's network config|"What are _my_ network settings?"|

## Typical Troubleshooting Order

1. **`ipconfig`** — Check your own device has a valid IP, gateway, and DNS.
2. **`ping` the gateway** — Confirm you can reach your local router.
3. **`ping` an external host** (e.g., `8.8.8.8`) — Confirm internet connectivity.
4. **`ping` a domain name** (e.g., `google.com`) — Confirm DNS resolution works.
5. **`tracert`/`traceroute`** — If something fails above, trace the path to find exactly where it breaks.

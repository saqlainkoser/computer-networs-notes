# 🔐🌐 HTTPS & DNS — Notes

---

## 🔐 HTTPS (Hypertext Transfer Protocol Secure)

> 📌 **Note:** HTTPS is **HTTP + encryption**. It's not a separate protocol from scratch — it's HTTP wrapped inside a **TLS/SSL** encrypted tunnel.

### What it does

- Encrypts data **in transit** between the browser (client) and the server.
- Verifies the server's **identity** using a digital certificate.
- Ensures data **integrity** — data can't be tampered with in transit without detection.

### Default port

```
443
```

(Plain HTTP uses port `80`)

### The 3 guarantees HTTPS provides

|Guarantee|What it means|
|---|---|
|**Encryption**|No one can read the data while it's traveling (protects against eavesdropping)|
|**Integrity**|Data can't be modified in transit without being detected|
|**Authentication**|You know you're actually talking to the real server, not an imposter|

> ⚠️ **Without HTTPS**, anyone on the same network (public Wi-Fi, ISP, attacker) can potentially read or modify the data — including passwords and payment info.

### How the TLS Handshake works (simplified)

```
1. Client Hello        → Client says "I want to connect securely" + supported ciphers
2. Server Hello        ← Server replies with its SSL certificate + chosen cipher
3. Certificate Check   → Client verifies the certificate with a trusted Certificate Authority (CA)
4. Key Exchange        → Client & server agree on a shared encryption key (session key)
5. Secure Connection   ✅ All further data is encrypted using that session key
```

### Key terms

- **SSL/TLS Certificate** — issued by a **Certificate Authority (CA)** (e.g. Let's Encrypt, DigiCert) to prove a domain's identity.
- **TLS (Transport Layer Security)** — the modern, secure replacement for the old SSL protocol. **⚠️ "SSL" today almost always actually means TLS.**
- **Symmetric vs Asymmetric encryption**:
    - **Asymmetric** (public/private key pair) is used briefly during the handshake to safely exchange a key.
    - **Symmetric** (single shared key) is used for the actual data transfer — it's much faster.
- **Padlock icon 🔒** in the browser = valid HTTPS certificate is active.

### Why it matters

- Required for SEO ranking (Google favors HTTPS sites).
- Required to use many modern browser features (camera, geolocation, service workers).
- **Protects login credentials, tokens, and personal data** from being intercepted.

## 🌐 DNS (Domain Name System)

> 📌 **Note:** DNS is often called the **"phonebook of the internet"** — it translates human-friendly domain names into machine-friendly **IP addresses**.

### What it does

When you type `www.example.com`, your computer doesn't actually know how to reach it directly — it asks DNS: _"What's the IP address for this domain?"_

```
www.example.com  →  DNS lookup  →  93.184.216.34
```

### Default port

```
53
```

(UDP for standard queries, TCP for larger transfers like zone transfers)

### The DNS Lookup Process (step by step)

```
1. Browser cache      → Checks if the IP is already cached locally
2. OS cache            → Checks the operating system's DNS cache
3. Recursive Resolver  → Usually your ISP's DNS server — does the searching for you
4. Root Name Server    → Points to the correct TLD server (.com, .org, etc.)
5. TLD Name Server     → Points to the domain's authoritative name server
6. Authoritative Server→ Returns the actual IP address for the domain
7. Response cached & returned to browser ✅
```

> 💡 **Tip:** This whole process usually takes **milliseconds** thanks to caching at every step.

### Common DNS Record Types

|Record|Purpose|
|---|---|
|**A**|Maps a domain to an **IPv4** address|
|**AAAA**|Maps a domain to an **IPv6** address|
|**CNAME**|Alias — points one domain to another domain name|
|**MX**|Specifies **mail servers** for the domain|
|**TXT**|Stores text data (often used for domain verification, SPF/DKIM email security)|
|**NS**|Specifies the **authoritative name servers** for the domain|

### Key terms

- **Domain Registrar** — where you buy/register a domain name (e.g. GoDaddy, Namecheap).
- **Nameserver** — a server that holds the DNS records for a domain.
- **TTL (Time To Live)** — how long a DNS record is cached before it's re-checked.
- **Propagation** — the time it takes for DNS changes to update across all servers globally (can take up to **48 hours**, though usually much faster).

### Why it matters

- **Without DNS**, you'd have to memorize IP addresses instead of names like `google.com`.
- DNS issues are one of the most common causes of a website appearing "down" even when the server is fine.

## 🔗 How HTTPS & DNS Work Together

```
1. You type: https://example.com
2. DNS resolves "example.com" → IP address (e.g. 93.184.216.34)
3. Browser connects to that IP over port 443
4. TLS handshake happens (HTTPS encryption begins)
5. Encrypted HTTP request/response is exchanged
```

> ⚠️ **DNS lookups themselves are usually NOT encrypted by default** — this is a privacy gap solved by newer standards like **DNS over HTTPS (DoH)** and **DNS over TLS (DoT)**, which encrypt the DNS query itself.

---

## 🧠 Key Takeaways

- **DNS** finds the address. **HTTPS** secures the connection once you get there.
- HTTPS = **HTTP + TLS encryption** — protects confidentiality, integrity, and authenticity of data.
- DNS = **domain name → IP address translator**, using a hierarchical lookup system (root → TLD → authoritative server).
- **Port 443** for HTTPS, **Port 53** for DNS.
- Modern privacy tools (**DoH/DoT**) now encrypt DNS queries too, closing a long-standing gap.

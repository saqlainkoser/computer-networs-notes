# OSI Model (Open Systems Interconnection Model)

The **OSI Model** is a conceptual framework developed by the **International Organization for Standardization (ISO)** that standardizes how different networking systems communicate with each other. It divides the communication process into **7 layers**, each with specific functions, so that data can be transmitted reliably from one device to another across a network.

---

## The 7 Layers of OSI Model

_(Remembered top-to-bottom as: **A**ll **P**eople **S**eem **T**o **N**eed **D**ata **P**rocessing, or bottom-to-top: **P**lease **D**o **N**ot **T**hrow **S**ausage **P**izza **A**way)_

|Layer No.|Layer Name|Data Unit|
|---|---|---|
|7|Application|Data|
|6|Presentation|Data|
|5|Session|Data|
|4|Transport|Segments|
|3|Network|Packets|
|2|Data Link|Frames|
|1|Physical|Bits|

---

## 7. Application Layer

### Function

- Closest to the end user; provides network services directly to applications.
- Enables processes like email, file transfer, and web browsing.

### Key Points

- Protocols: **HTTP, HTTPS, FTP, SMTP, DNS, Telnet**
- Interfaces between the network and the software applications the user interacts with.

---

## 6. Presentation Layer

### Function

- Also called the **translation layer**.
- Responsible for data formatting, encryption/decryption, and compression.

### Key Points

- Converts data into a format understandable by the application layer.
- Handles tasks like **encryption (SSL/TLS), compression, and character encoding (ASCII, JPEG, etc.)**.

---

## 5. Session Layer

### Function

- Establishes, manages, and terminates sessions (connections) between two devices.

### Key Points

- Handles **synchronization, dialog control** (who sends when), and session checkpoints.
- Ensures data from different applications isn't mixed.
- Examples: **NetBIOS, PPTP**

---

## 4. Transport Layer

### Function

- Provides reliable end-to-end data transfer between devices.
- Handles **segmentation, flow control, and error control**.

### Key Points

- Two main protocols:
    - **TCP (Transmission Control Protocol)** – connection-oriented, reliable, ordered delivery.
    - **UDP (User Datagram Protocol)** – connectionless, faster, no guarantee of delivery.
- Uses **port numbers** to identify specific applications/services.

---

## 3. Network Layer

### Function

- Responsible for **logical addressing** and **routing** of data (packets) between devices across different networks.

### Key Points

- Determines the best path for data using routing algorithms.
- Uses **IP addresses** for identification.
- Devices: **Routers**
- Protocols: **IP, ICMP, IPsec**

---

## 2. Data Link Layer

### Function

- Responsible for node-to-node data transfer and error detection/correction from the physical layer.
- Divided into two sublayers: **LLC (Logical Link Control)** and **MAC (Media Access Control)**.

### Key Points

- Uses **MAC addresses** for physical device identification.
- Organizes bits into **frames**.
- Devices: **Switches, Bridges, NICs**
- Protocols: **Ethernet, PPP**

---

## 1. Physical Layer

### Function

- Deals with the actual physical connection between devices.
- Transmits raw **bits (0s and 1s)** over a physical medium.

### Key Points

- Defines cables, connectors, voltage levels, and data rates.
- Devices: **Hubs, Repeaters, Cables, Connectors**
- Medium: copper cables, fiber optics, wireless signals.

---

## How Data Flows Through the OSI Model

1. **Sender side:** Data moves from **Layer 7 → Layer 1** (Application to Physical), with each layer adding its own header/trailer (this process is called **encapsulation**).
2. **Receiver side:** Data moves from **Layer 1 → Layer 7** (Physical to Application), with each layer removing the corresponding header/trailer (this process is called **decapsulation**).

```
Sender                          Receiver
Application  (Data)             Application
Presentation (Data)             Presentation
Session      (Data)             Session
Transport    (Segments)         Transport
Network      (Packets)          Network
Data Link    (Frames)           Data Link
Physical     (Bits)   ------->  Physical
```

---

## OSI Model vs TCP/IP Model (Quick Note)

|OSI Model (7 Layers)|TCP/IP Model (4 Layers)|
|---|---|
|Application, Presentation, Session|Application|
|Transport|Transport|
|Network|Internet|
|Data Link, Physical|Network Access|

---

## Summary

- The OSI Model has **7 layers**, each handling a specific part of network communication.
- It is a **conceptual/reference model**, not implemented directly in real-world networking (unlike TCP/IP model).
- Helps in **standardizing** communication, **troubleshooting** network issues, and understanding how data travels across a network.
